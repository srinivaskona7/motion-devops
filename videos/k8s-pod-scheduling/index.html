The scheduler decides where a Pod lands. The kubelet decides when it leaves.
CC

You run kubectl apply, and a Pod named checkout is created.

The API server saves it to etcd.

Then it sits at Pending: the object exists, but spec.nodeName is still empty.

Who chooses the machine?

The kube-scheduler, which watches for unassigned Pods.

And when a node runs short of memory, the kubelet may take checkout away.

Let's follow both halves.

Checkout enters the scheduling queue, ordered by priority.

Then Filter checks every node.

node-a has 300 millicores free; checkout requests 500, so node-a is out.

node-b and node-c are feasible.

Score ranks them: node-b 61, node-c 88.

Highest wins, ties break at random.

Reserve and Permit then hold that choice, so no other Pod claims it.

Bind writes node-c into spec.nodeName, and the kubelet there starts the container.

Had no node passed Filter, PostFilter would try preemption.

Three different forces can remove a Pod.

Preemption: the scheduler evicts lower-priority victims so a higher-priority Pod fits,

and records the target in nominatedNodeName.

Victims get their grace period, 30 seconds by default,

and PodDisruptionBudgets are best effort.

Node-pressure eviction: the kubelet sees a signal, like memory.available under 100Mi.

It ignores budgets, and a hard threshold means zero grace.

API-initiated eviction, used by kubectl drain, respects budgets and returns 429 when one would break.

Four edge cases.

Eviction order: Pods using more than they request go first,

by priority, then by how far over.

BestEffort Pods request nothing, so any usage counts as over.

QoS class is not the ranking key.

nominatedNodeName is a hint, not a reservation; a higher-priority Pod can take that node.

MemoryPressure becomes a NoSchedule taint, so new Pods stop landing there.

And the transition period, five minutes by default, stops that condition from flapping.

The whole loop: Queue, Filter, Score, Bind, Running.

Then Pressure, and Evicted: the Pod is marked Failed,

and its ReplicaSet creates a replacement that rejoins the queue.

Three habits keep you in control: set requests, use a PriorityClass,

add a PodDisruptionBudget.

To watch both halves, read the events: FailedScheduling from the scheduler,

Evicted from the kubelet.

The scheduler decides where a Pod lands.

The kubelet decides when it leaves.
