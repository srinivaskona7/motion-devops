05 · Recap

Three layers. One rehearsal.

Velero

namespaces · any cluster

PVC clone · snapshot

volume data

etcd snapshot

cluster state

Rehearse the restore.

CC

2 AM.

Traffic flows through the ingress to your pods.

Every object lives in etcd.

Then the etcd disk fails, and a bad migration corrupts the payments volume.

Three layers bring it back.

Layer one, cluster state.

etcdctl snapshot save writes the whole keyspace to one file.

Keep it off the cluster.

etcdutl snapshot restore rebuilds the data directory, and every object returns.

But not the bytes inside volumes.

Layer two, volume data.

A CSI driver can clone a claim: name payments-data as the dataSource,

same namespace, same storage class.

But a clone copies corruption too.

Restore from last night's VolumeSnapshot instead.

The pod remounts clean data.

Layer three, the whole app.

Velero already saved the shop namespace, manifests and volume snapshots, as k8s-daily.

One command: velero restore create, from backup k8s-daily.

Objects reapply, volumes rehydrate, and traffic turns green.

So: etcd snapshots for cluster state.

PVC clones for data.

Velero for whole namespaces, even on a new cluster.

And rehearse the restore, before 2 AM does it for you.
